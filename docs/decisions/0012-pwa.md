# 0012 — PWA : installable, ouverture hors ligne, mises à jour à la demande

**Contexte.** L'app s'utilise à la salle, souvent sans réseau. Les données y sont déjà (IndexedDB, ADR 0006) et se synchronisent toutes seules (ADR 0010). Il manquait l'application elle-même : sans réseau, le navigateur ne pouvait pas charger son HTML et son JavaScript.

**Décision.** `vite-plugin-pwa`, qui génère le service worker avec Workbox, la bibliothèque de référence.

- **Manifeste** (`manifest.webmanifest`) : nom, icônes, couleurs, `display: standalone` (plein écran, sans barre d'adresse), orientation portrait.
  - Les icônes PNG sont générées depuis le logo SVG (`npm run icons`), avec une version « maskable » que le téléphone découpe selon sa forme d'icône.
- **Service worker en « precache »** : au premier chargement, il copie dans le cache tous les fichiers du build (HTML, JS, CSS, polices, icônes). Ensuite, il sert l'app depuis ce cache, avec ou sans réseau.
  - Toute adresse de l'app (`/seance`, `/programmes/…`) retombe sur `index.html`.
  - **L'API n'est jamais mise en cache** : ses réponses sont privées et changent tout le temps. Les données passent par IndexedDB et la synchronisation.
- **Mises à jour à la demande** (`registerType: 'prompt'`).
  - Une nouvelle version est téléchargée en arrière-plan, mais l'ancienne reste active.
  - Un bandeau propose « Mettre à jour ».
  - On ne recharge jamais de force : une série pourrait être en cours de saisie.
  - L'app vérifie s'il existe une nouvelle version toutes les heures, car elle peut rester ouverte des jours.
- **Installation.**
  - Chrome, Edge et Android : bouton « Installer l'application » dans le Profil, via l'événement `beforeinstallprompt`.
  - iPhone : explication du menu Partager de Safari, car iOS n'offre pas de bouton.
- **Polices** : alphabet latin seulement. C'est suffisant pour le français (accents, œ, guillemets) et le cache passe de 53 à 25 fichiers.
- La date du build est affichée dans le Profil, pour savoir quelle version tourne sur un téléphone.

**Alternatives écartées.**

- *Mise à jour automatique* : rechargement dès qu'une version sort. Trop risqué en pleine séance.
- *Cacher les réponses de l'API* : cela ferait doublon avec IndexedDB, avec un risque de données périmées ou de données d'un autre compte après une déconnexion.

**Conséquences.**

- Pas de service worker en développement (`npm run dev`), sinon il masquerait les modifications du code. On le teste avec `npm run build` puis `npx vite preview`.
- Un service worker exige HTTPS, sauf sur `localhost`. Sur un téléphone, l'app devra donc être servie en HTTPS : c'est un sujet de déploiement.

**Mise à jour : découpage du JavaScript.** Le build produisait un seul fichier de 940 Ko. Il est maintenant découpé :

- **Les bibliothèques à part** (React, Chakra, Dexie). Elles changent rarement : d'une version à l'autre, le service worker ne retélécharge que les fichiers dont l'empreinte a changé, en général le code de l'app (quelques dizaines de Ko).
- **Les écrans chargés à la demande**, avec `lazy` dans le routeur. Seuls l'accueil et la connexion sont dans le premier fichier, ce qui réduit le code lu au démarrage.
- **Le hors ligne ne change pas** : tous les morceaux sont dans le precache dès l'installation.
